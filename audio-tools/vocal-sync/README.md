# VocalSync

Подгоняет **тайминг** вокальной дорожки (dub) под эталон (guide), как VocAlign или Revoice Pro. Высота тона не меняется. Программа выросла из VoxMatch: окно, перетаскивание в Cubase, плеер и комп из лучших фраз взяты оттуда. Движок выравнивания написан заново.

Типичный сценарий:
- **эталон** — вокал оригинала: стем Suno или результат сепаратора. Может быть с остатками инструментов и ревербом; он нужен только для анализа;
- **dub** — a cappella-кавер в Suno: тот же текст и мелодия, но другой тайминг (длиннее или короче вступление, темп «уплывает», отдельные фразы раньше или позже);
- после подгонки dub идёт в RVC, поэтому растяжение сделано максимально бережным: Rubber Band R3, пределы растяжения, плавная смена скорости.

Всё работает локально, без интернета и облачных API.

## Установка (macOS)

Нужны Python 3.10–3.12, Rubber Band и ffmpeg. Проще всего поставить их через Homebrew:

```bash
brew install python@3.11 rubberband ffmpeg
```

Затем дважды щёлкните **`start_mac.command`**. При первом запуске он создаст `.venv` и поставит библиотеки из `requirements.txt` (3–10 минут, нужен интернет). Если macOS не даёт открыть файл: правая кнопка → «Открыть».

Ручная установка:

```bash
cd ~/Desktop/"VocalSync"
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py            # окно
```

**Rubber Band.** Лучшее качество даёт Rubber Band CLI (`brew install rubberband`): движок R3 (`--fine`) с картой времени `--timemap`. Если CLI нет, программа использует ту же библиотеку через `pylibrb` (тоже R3, ставится из `requirements.txt`). Если нет и её, включается запасной метод WSOLA, а в отчёте и в окне выводится предупреждение о худшем качестве. Какие движки доступны, видно внизу панели ⚙.

**ffmpeg** нужен только для MP3/M4A, которые не читает libsndfile.

## Окно

```bash
./start_mac.command        # или .venv/bin/python app.py
```

1. **Эталон** перетащите в левую зону, **дубли** — в правую (можно несколько файлов или папку). Работает перетаскивание и из Finder, и прямо из Cubase. Если бросить несколько файлов в левую зону, первый станет эталоном, остальные — дублями.
2. Обработка начинается сама. Отключить автозапуск можно галочкой в ⚙; тогда жмите **«Выровнять»**.
3. Для каждого дубля создаётся папка `output/<имя>_<дата-время>/` (описание файлов ниже).
4. **Карточка «Результат»**:
   - «Слушать»;
   - **«В Cubase»** — зажмите и перетащите на дорожку: файл ляжет с нуля, ровно под эталон;
   - **«Экспорт WAV…»** — сохранить копию куда угодно;
   - «Папка»;
   - «График» — открывает alignment.png.
5. **Таймлайн** (колёсико — масштаб, Shift+колёсико — прокрутка, протянуть мышью — петля, двойной клик — весь файл):
   - сверху эталон (оранжевый) и dub после выравнивания (бирюзовый);
   - ниже dub «до», сдвинутый только на общий сдвиг;
   - внизу кривая локального растяжения с пределами;
   - красные полосы — места с предупреждениями.
6. **Отчёт** слева: сдвиг, темп, растяжение, качество до и после. Клик по предупреждению показывает этот участок и проигрывает его по кругу.
7. **Плеер:**
   - клавиши: **1** эталон, **2** dub до, **3** результат, **4** комп;
   - **E** — подмешать эталон тише;
   - **S** — стерео L/R: эталон слева, dub справа, как в `preview_stereo.wav`;
   - **L** — петля, **пробел** — пуск/пауза.
8. **Комп** (галочка в ⚙, нужно ≥ 2 дублей): эталон режется на фразы, каждая фраза каждого дубля получает оценку. Колёсико на блоке ленты листает варианты, правый клик показывает список, «↺ Лучшие» сбрасывает ваши замены. Файл компа: `output/<эталон> — КОМП.wav`.

Сессия (файлы и настройки) запоминается и открывается при следующем запуске.

## Командная строка

```bash
.venv/bin/python align.py --guide g.wav --dub d.wav
.venv/bin/python align.py --guide g.wav --dub d1.wav --dub d2.wav --dub d3.wav     # пакет
.venv/bin/python align.py --guide g.wav --dub d.wav --tightness 90
.venv/bin/python align.py --guide g.wav --dub d.wav --mode global                  # только сдвиг+темп
.venv/bin/python align.py --guide g.wav --dub d.wav --anchors a.csv                # опорные точки
.venv/bin/python align.py --guide g.wav --dub d.wav --start 60 --end 90            # один припев
.venv/bin/python align.py --guide g.mp3 --dub d.flac --no-chroma --float --sr 48000
.venv/bin/python align.py --guide g.wav --dub d.wav --preset "Плотный дабл"
```

`--help` выводит все параметры. Анализ эталона в пакетном режиме делается один раз.

### Опорные точки (anchors.csv)

```
guide;dub
# время в эталоне ; время в dub (секунды или м:сс.мс, запятая или точка)
1:05,0;1:07,9
80.0;82.7
```

Карта проходит точно через эти точки, а поправка плавно гаснет за 1,5 с вокруг них. Файл `timemap.csv` из результата имеет тот же формат: его можно открыть, поправить строку на проблемной фразе и подать обратно через `--anchors`.

## Параметры

| Параметр (окно / CLI) | По умолчанию | Что делает |
|---|---|---|
| Режим / `--mode` | auto | `auto` — сдвиг, темп и каждый слог; `global` — только сдвиг и постоянный темп (для равномерного дрейфа); `anchors` — с опорными точками из CSV |
| Tightness / `--tightness` | 100 | Смесь глобальной карты (сдвиг + темп) и точной карты DTW. 100 — максимально точно. 90 — остаётся 10 % каждого отклонения (фраза, спетая на 300 мс позже, станет позже на 30 мс). 0 — только сдвиг и темп |
| Растяжение, × / `--stretch-min`, `--stretch-max` | 0.67 – 1.5 | Пределы локального коэффициента растяжения (длительность результата / исходника). Шире — точнее на сильно «уехавших» фразах, но больше артефактов |
| Сглаживание / `--smooth-ms` | 40 мс | Сглаживание карты DTW. Меньше — точнее по слогам, больше — спокойнее |
| Плавность растяжения / `--rate-smooth-ms` | 150 мс | За какое время коэффициент растяжения может смениться (ограничение скорости изменения). Больше — меньше «плавания» звука, полезно перед RVC |
| Опорные точки, шаг / `--keyframe-ms` | 60 мс | Карта прореживается до опорных точек: сетка с этим шагом в звучащих местах, плюс атаки слогов эталона и края пауз. Между точками — линейно |
| `--no-onset-keys` | — | Не добавлять опорные точки на атаках |
| Веса chroma / MFCC / онсеты / энергия, `--w-*` | 0.5 / 1 / 0.4 / 0.4 | Из чего складывается сравнение кадров: ноты, тембр и фонемы, атаки слогов, громкость |
| `--no-chroma` | — | Без нот — если кавер в другой тональности |
| `--band-ms` | 250 мс | Ширина точного поиска вокруг грубого пути |
| `--silence-db` | 35 дБ | Тишина — ниже пика файла на столько дБ, но не ниже шумового пола файла (подстраивается сам) |
| Фрагмент / `--start`, `--end` | весь | Обработать только кусок эталона. Результат — длиной с фрагмент; в DAW его ставят на позицию `start` |
| Выход / `--float`, `--sr` | 24 бит, частота эталона | Формат и частота `dub_aligned.wav` |
| Движок / `--engine` | auto | `cli` → `pylibrb` → `wsola` |
| Питч / `--pitch` | 0 | Подтянуть ноты к эталону (из VoxMatch; для RVC обычно не нужно) |
| Комп (окно) | выкл. | Собрать комп из лучших фраз нескольких дублей |

**Пресеты** (⚙ или `--preset`):
- «Для RVC — точно и чисто» (стандарт);
- «Точно в ноль — по слогам»;
- «Плотный дабл»;
- «Естественный дабл»;
- «Только сдвиг и темп»;
- «Другая тональность (без chroma)»;
- «Грязный эталон (сепаратор, реверб)».

## Что лежит в output/<имя>_<дата-время>/

| Файл | Что это |
|---|---|
| `dub_aligned.wav` | Подогнанный dub: все каналы исходника, частота эталона (или `--sr`), 24 бит или float32. Длина ровно равна длине эталона, начало с нуля: ложится в DAW без сдвига |
| `preview_stereo.wav` | Эталон в левом канале, подогнанный dub в правом: проверка на слух в наушниках |
| `preview_mix.wav` | Обе дорожки вместе (пик −1 dBFS) |
| `timemap.csv` | Опорные точки карты: `время в эталоне; время в dub; растяжение` |
| `report.txt`, `report.json` | Отчёт (как его читать — ниже) |
| `alignment.png` | Путь DTW, кривая растяжения, огибающие до и после |

## Как читать отчёт

- **Сдвиг начала** — где в dub звучит тот же момент, что и в эталоне. «+2,1 с» значит, что в dub это на 2,1 с позже (вступление длиннее).
- **Темп dub** — на сколько процентов dub медленнее или быстрее в среднем (равномерный дрейф).
- **Растяжение** — среднее, минимум и максимум локального коэффициента, доля времени с растяжением сильнее ±20 % и наибольшее изменение за 100 мс. Чем ближе к 1 и чем плавнее, тем меньше артефактов.
- **Расхождение с путём DTW** (медиана, мс): «как есть → только сдвиг → сдвиг+темп → после». Показывает, сколько дал каждый шаг. «После» — насколько итоговая карта отличается от найденной DTW: при tightness 100 это обычно единицы миллисекунд.
- **Ошибка совпадения атак** — для каждой атаки слога эталона ищется ближайшая атака dub в окне ±100 мс. Указаны средняя и медиана |Δ| и доля атак, нашедших пару, до и после. Это независимая проверка по звуку результата.
- **Предупреждения** с таймкодами эталона:
  - *тональность отличается* — включите «без chroma»;
  - *в эталоне есть пение, в dub тишина* или *структура расходится* — пропущенная или лишняя фраза;
  - *dub плохо похож на эталон* — другие слова, шум, артефакты сепаратора;
  - *упёрлись в предел растяжения* — фраза уехала сильнее, чем позволяют пределы. Поставьте опорную точку или расширьте пределы.

**Как читать alignment.png:**
- верхний график — отклонение пути DTW и итоговой карты от общей линии «сдвиг + темп» (горбы — фразы, спетые раньше или позже);
- второй — коэффициент растяжения с пределами;
- третий и четвёртый — огибающие громкости эталона и dub до и после; после выравнивания они должны совпадать;
- красные полосы — предупреждения.

## Как это устроено

```
vocalsync/
  io.py        чтение/запись (WAV/FLAC/AIFF/OGG/MP3, ffmpeg-запасной), ресемплинг soxr
  features.py  анализ: моно → 24 кГц → полоса 80 Гц–8 кГц → нормализация; кадры 5 мс:
               MFCC+дельты, chroma (CENS-подобная), онсеты, энергия; тишина по RMS
  coarse.py    сдвиг + темп: корреляция огибающих онсетов с перебором темпа ±6 %;
               устойчивая (Huber) прямая по пути DTW
  dtw.py       DTW в полосе вокруг пути, многомасштабный: 80 мс → 20 мс → 5 мс
  path.py      постобработка: паузы — линейно, сглаживание, tightness, опорные точки,
               пределы растяжения, плавность скорости, прореживание до опорных точек
  warp.py      Rubber Band R3: CLI --timemap (параллельно кусками по паузам) / pylibrb /
               WSOLA; все каналы, исходное качество, без изменения высоты
  report.py    WAV, превью, timemap.csv, report.txt/json, alignment.png
  pipeline.py  сборка шагов, диагностика, метрики, кэш анализа
  pitch.py, world.py   питч (необязательно, из VoxMatch)
  comp.py      комп из лучших фраз (из VoxMatch Простой)
  ui.py        окно (PySide6)
align.py       командная строка        app.py   окно
```

**Почему свой DTW, а не `librosa.sequence.dtw` или synctoolbox (MrMsDTW).**
- `librosa.sequence.dtw` строит полную матрицу N×M. Для 4 минут при шаге 5 мс это около 2,3 млрд ячеек, то есть 9 ГБ во float32, и полосы вокруг произвольного пути там нет.
- synctoolbox реализует ту же идею (грубо → точно в полосе), но тянет тяжёлые зависимости, заточен под chroma/DLNCO музыкальных записей и не учитывает паузы вокала.
- Здесь DTW на numba идёт в полосе вдоль пути предыдущего уровня, память O(N·полоса): 4 минуты — около 700 МБ на весь процесс. Кадры, где молчат обе дорожки, ничего не стоят. Если путь прижался к краю полосы, поиск сам расширяется.

**Тишина и хвосты.** Карте DTW программа доверяет только там, где поют обе дорожки (громче −25 дБ от пика). Хвосты реверба эталона, затухания dub и паузы заполняются линейно, поэтому тишину не «дёргает».

## Проверка качества

```bash
.venv/bin/python -m pytest -q tests          # автотесты (≈1 мин)
.venv/bin/python tests/quality.py            # таблица точности на синтетике
.venv/bin/python tests/quality.py --real ~/Music/вокал.wav   # + реальный вокал
.venv/bin/python tests/bench.py              # 4 минуты: время и память
```

**Синтетика (`tests/synth.py`).**
- «Певец» поёт фразы слогами: шумовая согласная плюс гласная с формантами, вибрато и подъездом к ноте.
- Dub — тот же текст другим голосом (другие форманты, вибрато, лёгкая расстройка, стерео).
- Известное искажение времени: сдвиг 0,5–3 с, темп ±1–3 %, кусочно-случайные локальные отклонения ±5–10 %.
- В эталон подмешаны реверб и «остатки инструментов» (пэды, бочка).
- Ошибка считается по известной карте в звучащих местах.

Результаты на этом Mac (Apple M1, 8 потоков):

| Случай | Медиана | 95-й перц. |
|---|---|---|
| сдвиг +1,7 с, темп +2 %, локально ±5–10 % | 6,4 мс | 25,9 мс |
| сдвиг −0,6 с, темп −3 %, локально ±5–10 % | 5,5 мс | 17,7 мс |
| сдвиг +3,0 с, темп +1 %, локально ±5–10 % | 6,4 мс | 27,1 мс |
| сдвиг +0,5 с, темп −1 %, локально ±5–10 % | 6,0 мс | 22,6 мс |
| сдвиг +2,2 с, темп +3 %, без локальных | 6,6 мс | 20,4 мс |
| реальный вокал (стем 3 мин, искажён Rubber Band по известной карте) | 3,8 мс | 8,9 мс |
| критерий | < 20 мс | < 50 мс |

- **4-минутный трек** (стерео dub, 44,1 кГц): выравнивание 11–24 с (в зависимости от загрузки Mac) плюс экспорт с графиком около 1,5 с; пиковая память процесса 670–710 МБ. Растяжение R3 занимает бо́льшую часть времени и идёт параллельно кусками по паузам.
- **Длина выхода** всегда равна длине эталона (проверяется в тестах).
- **Щелчки:** самый резкий скачок между сэмплами — не больше 1,6–2,3 типичного; на стыках кусков кроссфейд 20 мс в тишине, по краям — 5 мс.
- Тесты также проверяют:
  - режимы global и anchors;
  - фрагмент `--start/--end`;
  - чтение CSV с десятичной запятой;
  - что timemap.csv читается как опорные точки;
  - предупреждение о другой тональности;
  - запасной WSOLA.

## Ограничения

- Программа подгоняет только тайминг. Если в dub пропущена или добавлена фраза, она сообщит об этом с таймкодом, но «вырезать лишнее» сама не станет: поставьте опорные точки или поправьте дубль.
- При tightness ниже 100 часть каждого отклонения остаётся намеренно — это смесь, а не «мягкость».
- Комп и питч перенесены из VoxMatch и по умолчанию выключены. Покадровая правка тайминга и питча по фразам («Гибкий режим» VoxMatch Простой) не перенесена.
