# Voice Dataset Builder (`voiceset`)

Берёт 10–20 минут **сухой записи вашего пения** (несколько песен) и собирает из неё:

1. **`out/suno/voice_set_2min.wav`**: ровно 2:00 сбалансированного набора для **Suno Voices** (моно, 48 кГц, 24 бит);
2. **`out/rvc/dataset/*.wav`**: очищенный полный датасет для обучения **RVC (Applio)**.

Плюс отчёт `out/report/report.html` с плеером у каждой фразы: слушаете прицельно и исключаете то, что не нравится.
Полное ТЗ: [SPEC.md](SPEC.md).

> Программа **не** тюнит высоту, не растягивает время, не добавляет эффекты, не обучает модели и ничего не загружает в Suno. Загрузка в Suno и проверка голоса: руками.

## Быстрый старт (самый простой путь)

1. Скачайте репозиторий (зелёная кнопка **Code → Download ZIP**) и распакуйте.
2. Откройте папку `voice-dataset-builder`.
3. Положите свои записи (WAV/FLAC) в папку **`input/`** (создастся при первом запуске). Один файл = одна песня.
4. Запустите:
   - **macOS**: двойной клик по `Запустить.command` (если macOS ругается: правый клик → «Открыть»);
   - **Windows**: двойной клик по `Запустить.bat`.
5. Первый запуск ставит зависимости (5–10 минут, нужны Python 3.10–3.12 и интернет). Потом откроется отчёт, а файл для Suno будет в `out/suno/voice_set_2min.wav`.

Нужен Python: [python.org/downloads](https://www.python.org/downloads/) (на Windows при установке отметьте «Add python.exe to PATH»).

## Ручная установка

```bash
cd voice-dataset-builder
python3 -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e .                                          # + [ecapa] [asr] [dev] по желанию
voiceset all input -o out
```

## Как записывать

- 10–20 минут, 6–8 песен в том **стиле и на том языке**, в котором будут релизы.
- **Сухо**: без реверба, автотюна и компрессии; один микрофон, 20–30 см, тихая комната без эха.
- Пики примерно от −9 до −3 dBFS, без перегруза. Громкость обычная для песни, не шёпот и не крик.
- В основном обычная подача + немного «с опорой» и «с придыханием».
- **Весь диапазон**, отдельно допойте самые низкие и самые высокие ноты. Длинные ноты, пара быстрых мест.
- Без речи, смеха и выкриков. Перед записью распеться и попить воды.
- Формат: WAV/FLAC, 44,1/48 кГц, лучше 24 бит. Имя файла: `03_zvezda_Am.wav` (номер_песня_тональность) или `songs.csv` (колонки `file,song,key,style`).

## Команды

```bash
voiceset all input -o out                      # всё сразу: анализ → Suno → RVC → отчёт
voiceset analyze input -o out                  # нарезка + все признаки → out/work/analysis.parquet
voiceset calibrate out --labels labels.yaml    # дообучить классификатор подачи по вашей разметке
voiceset build-suno out --length 120 --seed 42 [--exclude 12,37] [--include 5]
voiceset build-rvc out --sr 48000              # или 40000; --combined = ещё и один общий WAV
voiceset report out
```

`--config my.yaml` на любой команде: переопределяет значения из `voiceset/default_config.yaml` (все пороги и веса там; копия использованных значений кладётся в `out/config.used.yaml`).
`-v` включает подробный вывод; причины отбора/отбраковки каждой фразы всегда пишутся в `out/log.txt`.

## Цикл правки

1. Откройте `out/report/report.html`, послушайте выбранные фразы.
2. Назовите номера (**id**), которые не нравятся: `voiceset build-suno out --exclude 12,37 --include 5`
   (или правьте `out/review.yaml`: `keep` — взять, `ban` — не брать; правка сохраняется между сборками).
3. Пересборка детерминирована: тот же вход и seed → побайтно тот же файл. Отчёт показывает разницу с прошлой сборкой.
4. Подача определяется плохо? Разметьте по 3–5 примеров каждого типа в `labels.yaml` и запустите `calibrate`:

```yaml
- {file: 03_zvezda_Am.wav, start: 12.4, end: 16.0, label: breathy}   # breathy | normal | power
- {file: 03_zvezda_Am.wav, start: 31.0, end: 35.5, label: power}
```

## Как это работает

| Этап | Что делает |
|---|---|
| Загрузка | моно, 48 кГц, удаление DC, срез ниже 70 Гц |
| Нарезка | Silero VAD (если он «не видит» пение: порог энергии), склейка пауз < 250 мс, фразы 1,5–8 с, деление в минимуме энергии, запас 40 мс |
| Высота f0 | RMVPE → torchcrepe → pyin (первый доступный), шаг 10 мс, медианный фильтр; ноты, вибрато, срывы |
| Громкость | LUFS, пик, крест-фактор |
| Подача | HNR, CPPS, наклон спектра, певческая форманта, громкость → правила по z-оценкам вашего голоса или kNN по `labels.yaml` |
| Брак | перегруз, щелчки, шум (SNR), реверб, срывы высоты. Каждый с кодом причины |
| Сходство | эмбеддинг ECAPA (SpeechBrain), без него: MFCC-статистики. Флаг «не похоже» |
| Suno 2:00 | покрытие диапазона (края ×2) + квоты подач 70/15/15 + ≤ 20% из одной песни → жадный отбор и локальный поиск → порядок по правилам → склейка (−20 LUFS, затухания 15 мс, зазоры 60 мс, пик ≤ −3 dBFS) → точная длина 120,0 с |
| RVC | все чистые фразы, −20 LUFS, клипы 2–12 с, без перемешивания; предупреждение, если меньше 10 минут |

Коды брака: `CLIP` перегруз · `CLICK` щелчок · `NOISE` шум фона · `REVERB` реверб · `PITCH` срывы высоты · `UNVOICED` нет озвученных кадров · `SHORT` слишком коротко · `LOWSIM` не похоже на голос.

### Необязательные модели

- `pip install -e ".[ecapa]"`: настоящие эмбеддинги ECAPA (вес ~80 МБ скачивается при первом запуске).
- `pip install -e ".[asr]"` + `--asr`: слова фраз через faster-whisper (в отчёт и `analysis.parquet`).
- Всё работает на **CPU**; GPU не нужен. 15 минут записи анализируются за ~4 минуты на 4 ядрах.

## Проверка на тестовой записи

```bash
python scripts/make_samples.py --out samples   # синтетическая «запись» ≈ 15 мин (это не голос!)
voiceset all samples -o out
```

## Тесты

```bash
pip install -e ".[dev]" && pytest
```

Проверяются на синтетическом звуке с известным ответом: высота (< 30 центов), нарезка (число фраз и границы ±20 мс), перегруз/щелчки, подача (больше шума → breathy), склейка (нет скачка, пик ≤ −3 dBFS), длина 120,0 ± 0,2 с (моно, 48 кГц, 24 бит), отбор (квоты ±5%, соседи из разных песен, покрытие ≥ 90%), детерминизм (одинаковый хэш).

## Ограничения

- Подача определяется эвристикой: будут ошибки. Поэтому есть калибровка и прослушивание.
- Красоту исполнения программа не оценивает: решаете вы на слух.
- RMVPE и DNSMOS в этой версии не реализованы (RMVPE пропускается, дальше torchcrepe/pyin).
- Правила отбора основаны на опыте одного экспериментатора с Suno v5.5 (см. SPEC.md); для v6 проверяйте A/B.
- Только свой голос: Suno сверяет образец с голосом при проверке.
